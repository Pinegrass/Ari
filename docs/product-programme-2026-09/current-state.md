# Ari / Tomo — source and public-product audit

Audit started 11 September 2026. Baselines: mobile `4b4ae8e0a5139e3cfb3b61d80d9e4124f6cdb15c`, backend `1d5ba6b`, web `be5f32a`. Existing web payment verification and association edits are preserved. Production revisions, authenticated production journeys and store delivery are UNVERIFIED in this programme unless explicitly recorded in validation.md. This is a source audit, not certification of every line or live infrastructure.

1. **Existing capabilities:** Expo 57 mobile, Next 16 web, Flask/SQLAlchemy API and Supabase identity/data. Mobile offline local ledger/outbox/reconciliation; manual, voice, shared-text capture; budgets, recurring entries, local bills, goals, accountant ledger/P&L, tax tools, notes, groups/settlement links, export/deletion, Tomo chat, caching, country/currency formatting. Navigation connects accountant tools and reports. Web has authenticated dashboard, capture, budgets, Tomo, goals, tax, notes, P&L and settings.
2. **Partial capabilities:** daily/rolling-week/month-to-date report API with totals, timeline, top categories, comparison and live goals; separate AI weekly/monthly coaching. Neither is a complete financial review. No quarter/year report. Local bills are not authoritative backend obligations; no opening balance history or confirmed payday model. Country formatting exists, language translation does not. Bank aggregation has Setu configuration/consent gates; source is not evidence of a functioning production bank connection.
3. **Broken/inconsistent flows:** mobile periodic report uses absolute currency formatter for net, so a deficit looks positive. Web P&L spending direction labels are reversed. Period query inputs can produce 500s. Web and mobile reports differ. Existing mobile ledger/private-chart fixes and backend expense/payment fixes predate this programme; device retest remains pending. Browser began logged out; an existing authenticated session later became available and the live Reports journey was inspected read-only. No fresh signup, payment, financial edit or full authenticated journey is claimed.
4. **UX weaknesses:** accountant hierarchy hides useful reviews; capture and report narratives compete with broad tax/P&L/group tooling. Public homepage (browser observed) combines Play download, Open web, signup and two waitlists; abstract AI-coach promise; illustrative phone lacks sample-data label; weak trust explanation; no FAQ. Existing forest/coral identity is worth retaining.
5. **Architecture weaknesses:** independent client state and reporting implementations; generated recurring entries versus explicit obligations lack shared truth; no payday/safe-to-spend contract; backend notification jobs lack a common preference/frequency/quiet-hour policy. Current ORM comments still say Razorpay deprecated despite working web-provider source. Source overrides stale docs. Financial calculations mix Decimal and float; new synthesis should aggregate Decimal before JSON conversion.
6. **Instrumentation:** mobile PostHog facade already owns named capture/onboarding/nudge/report/paywall/push events and privacy opt-out; no equivalent web event contract. SDK presence does not prove collected data, retention dashboards or event quality. Last API activity is not the same as a meaningful app visit. Do not record raw financial figures, merchants, descriptions or chat text in analytics.
7. **Monetisation:** existing RevenueCat mobile path and Razorpay web subscriptions/webhook/verification/reconciliation, server tier state and feature gates. Configuration, provider reconciliation and actual paid lifecycle UNVERIFIED. Do not change pricing, trial mechanics, restrictions or providers in this programme.
8. **Notifications/retention:** Expo push token registration, server weekly/monthly/anomaly/budget/recurring/reactivation jobs, local bill reminders, three weekly check-ins, dismissals, streaks and referrals. Global push opt-out exists. Several jobs send AI summaries or merchant/amount text to lock-screen previews. No unified durable delivery ledger, channel/category preferences or quiet hours.
9. **Reporting:** weekly and monthly are partially implemented; quarterly and yearly absent at audit baseline. P&L charts are not synthesis. Current reports do not know complete balances, true savings, safe-to-spend changes, complete obligations or payday. Never relabel recorded net flow as cash available. Missing data must remain unknown.
10. **Opportunity:** close the capture → understandable review → correct information → useful next action loop. Explain exactly which data supports each observation. Add comparable period reviews and trustworthy boundaries before forecasting. Keep proactive insights deterministic where possible and let AI explain evidence, never invent it.

## Journeys and trust boundaries

- First use: welcome/onboarding → Supabase sign-in/profile → local ledger hydration → capture → synced summaries. Meaningful activation requires a reviewed money picture, not merely an account or a streak.
- Regular use: fast capture → Home/budgets → accountant/report → Tomo or corrected entry. Offline writes use a queue; reconnect reconciliation and account isolation are critical regression paths.
- Retention: scheduler → cached brief/push → notification routing → relevant screen. Local reminders and server notifications currently have separate controls.
- Upgrade: mobile store/RevenueCat or web checkout → backend verification/webhook → tier. Client payment success alone never grants access.
- Data rights: export and reauthenticated account deletion exist; production cascading deletion, backup retention/restoration and provider data retention require operational verification.

## Security scope

Source contains JWT verification, ownership-filtered finance queries, secure mobile token storage, production secret guard, rate limits, PII scrubbing for parsing, and signed provider webhooks. These controls are implemented, not independently security-certified. Audit priorities: notification preview privacy; analytics minimisation/fail-closed hydration; user isolation and report input validation. Encryption at rest, backups, restoration, live RLS coverage, provider logs and full deletion are operational evidence gaps. No secrets or customer records are copied into this report.
